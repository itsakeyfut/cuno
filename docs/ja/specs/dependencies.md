# 依存ライブラリ管理

> MVP の範囲外。「依存管理 段階 1」から実装する（時期の表記は [README.md](README.md)）。

## 方針: 両立型

- **cuno 形式のパッケージ**（`Cuno.toml` を持つもの）は、cuno 自身がビルドする。
- **既存ライブラリ**（SDL3、FFmpeg 等）は、レシピに書かれたビルド方法に従い、cuno が裏で既存のビルドシステム（CMake 等）を呼ぶ。
- 利用者は CMake を一切見ない。

## 段階

1. **Git / URL 直接指定**
   - `cuno add --git <URL>` などで依存を追加する。
   - ハッシュ値は cuno が自動で取得し、ロックファイルに記録する。
2. **レシピインデックス**
   - Git リポジトリ上にレシピのインデックスを置く（vcpkg の ports / crates.io-index 相当）。
   - `cuno add sdl3` だけで追加できる。
   - レシピには既存ライブラリのビルド方法を記述する。
   - 依存をリポジトリ内にコピーする `cuno vendor` もこの段階で提供する（[commands.md](commands.md)）。
3. **公開パッケージサービス**（将来）
   - crates.io のようなサービスは、利用者が増えてから検討する。

## バージョン

- **1 ライブラリ 1 バージョン**: C/C++ では同じライブラリの複数バージョンを共存させるとシンボルが衝突するため、依存グラフ全体で 1 ライブラリ 1 バージョンに解決する。両立できない場合は、どの依存同士が衝突しているかを示してエラーにする。
- **バージョン指定**: cargo と同じ書き方（例: `"3.2"` は 3.2 以上 4.0 未満）。
- セマンティックバージョニングに従わないライブラリは、レシピ側で互換範囲を宣言する。
- Git 依存は tag / commit で固定する。

## ロックファイル

- `Cuno.lock`（TOML）。解決したバージョン・取得元・ハッシュ値を記録する。
- Git へのコミットを推奨する。

## リンク方式

- 既定は**静的リンク**。依存ごとに `link` で変更できる。
  ```toml
  [dependencies]
  ffmpeg = { version = "7.1", link = "dynamic" }   # リンク方式（static / dynamic）
  ```
  - `static`: 静的リンク。依存を実行ファイルに取り込む。既定値。
  - `dynamic`: 動的リンク。依存を DLL / 共有ライブラリとして実行時に読み込む。
- **ライセンス**: cuno は依存のライセンスを表示する。LGPL（FFmpeg 等）のように、静的リンクで配布すると問題になりうる場合は警告する。

## features（条件付き機能）

- cargo と同じ仕組み。
  ```toml
  [dependencies]
  sdl3 = { version = "3.2", features = ["audio", "vulkan"] }
  ```
- レシピ側で、各 feature をライブラリのビルドオプションに対応付ける。

## システムライブラリ（Vulkan SDK 等）

- 既定は、再現性のためにレシピからソースビルドする。
- `system` で、インストール済みのものを使うかを指定できる。
  ```toml
  [dependencies]
  vulkan = { version = "1.4", system = true }   # インストール済みのものを使うか（true / false）
  ```
  - `true`: インストール済みのものを使う（`VULKAN_SDK` 等の環境変数から検出）。
  - `false`: レシピからソースビルドする。既定値。

## バイナリキャッシュ

- ビルド済みの依存をマシン内でキャッシュし、プロジェクト間で再利用する。
- チーム・CI での共有キャッシュは将来。
